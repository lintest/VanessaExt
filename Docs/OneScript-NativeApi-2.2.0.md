# OneScript 2.2.0 и NativeApi: что закрыто, что осталось

Дата: 2026-11-01.
Контекст: VanessaExt переводит автотесты компоненты на OneScript 2.2.0
(`.github/workflows/build.yml`, шаги «Установка OneScript», `tests/oscript/runner.os`).

Источники:

- issue [#1359](https://github.com/EvilBeaver/OneScript/issues/1359) — закрыт 2026-09-01
  как выполненный;
- коммит [`a8f6d586`](https://github.com/EvilBeaver/OneScript/commit/a8f6d586774e7e41fd2ebbca2fe86fef7d36beab)
  «Исправить совместимость Native API с 1С (#1359)», вошёл в релиз
  [v2.2.0](https://github.com/EvilBeaver/OneScript/releases/tag/v2.2.0);
- открытые PR: [#1790](https://github.com/EvilBeaver/OneScript/pull/1790) (передача
  параметров при вызовах), [#1760](https://github.com/EvilBeaver/OneScript/pull/1760)
  (сборка и macOS).

## 1. Что вошло в 2.2.0 (по коммиту a8f6d586)

| Что | Где в коде OneScript | Следствие для нас |
|---|---|---|
| Делегаты колбэков закреплены полями компоненты | `NativeApi/NativeApiComponent.cs` (`_onError`, `_onEvent`, `_onStatus`) | вызовы из нативного кода переживают сборку мусора |
| Массивы tVariant выделяются занулёнными, освобождаются по количеству | `NativeApiProxy.cpp` (`LMEM_ZEROINIT`/`calloc`, `FreeVariant(ptr, count)`), `NativeApiVariant.cs` (`_count`) | нет мусора в неинициализированных слотах |
| Out-параметры возвращаются в скрипт после вызова | `NativeApiComponent.WriteBackParameters` в `CallAsProcedure` и `CallAsFunction`; параметры объявлены `.ByValue(false)` | меняется поведение **всех** параметров методов, не только объявленных выходными |
| Регистрация типов по имени расширения | `NativeApiLibrary.RegisterComponents` через `GetExtensionName` → `RegisterExtensionAs` | `Новый("AddIn.<ид>.<ИмяРасширения>")` работает, как в 1С; при несовпадении регистрируются оба имени |
| Жизненный цикл библиотек | `IEngineLifetime`, `NativeApiFactory : IEngineLifetime` как сервис движка, `ScriptingEngine.Dispose` обходит сервисы | библиотека выгружается вместе с движком, а не навсегда |
| Обмен значениями типа Дата | `SetVariantDate` (OADate), чтение `VTYPE_DATE` и `VTYPE_TM` (`TmToOleDate` через `mktime`) | даты ходят в обе стороны |
| Разделение managed/unmanaged освобождения | `NativeApiLibrary.DisposeManagedResources` / `ReleaseUnmanagedResources` | повторный Dispose не роняет процесс |

## 2. Что осталось и где риски для VanessaExt

### 2.1. Семантика by-ref параметров ещё правится (PR #1790 не влит)

PR #1790 (открыт, в 2.2.0 не вошёл) заявляет: «By-reference arguments now update the
corresponding supplied arguments», «Argument values are no longer copied back into the
supplied array after a call, including when the call fails». То есть поведение
аргументов по ссылке в вызовах (рефлектор и стековая ВМ) продолжает меняться.

Риск: в 2.2.0 возможны расхождения с 1С, когда метод компоненты меняет параметр,
а скрипт передал не переменную, а выражение или литерал.

Проверка: тесты `Функц`/`Проц` в `Example/Forms/xUnitBDD/Ext/Form/Module.bsl`
(объявления 323 и 359) — прогнать сценарий с выходным параметром, переданным
выражением, и сверить с поведением платформы 1С.

### 2.2. При регистрации библиотеки конструктор компоненты вызывается дважды

`NativeApiLibrary.RegisterComponents` для каждого класса делает
`GetClassObject(...)` → `GetExtensionName(ptr, ...)` → `DestroyObject(ptr)`.
Только потом скрипт создаёт экземпляр через `Новый`.

Риск: если конструктор компоненты имеет побочные эффекты (открытие файлов или
сокетов, регистрация глобальных обработчиков, инициализация статики), они
выполнятся дважды — один раз «вхолостую».

Проверка: прогнать `runner.os` и посмотреть, не появляется ли в выводе следов
двойной инициализации; при наличии — вынести побочные эффекты из конструктора
в ленивую инициализацию при первом обращении к методу.

### 2.3. `VTYPE_PSTR` теперь отдаётся как двоичные данные, а не строка

В `NativeApiProxy.cpp` ветка `case VTYPE_PSTR:` изменилась с `e(...)` (пустое
значение) на `x(variant, number, v->pstrVal, v->strLen)`, то есть в C# попадает
через колбэк blob и превращается в `ДвоичныеДанные`.

Риск: 1С показывает `VTYPE_PSTR` как `Строка`. Если какой-либо метод VanessaExt
возвращает ANSI-строку (`VTYPE_PSTR`), в OneScript тип будет `ДвоичныеДанные`,
и проверки `ИмеетТип("Строка")` / `Равно(...)` дадут ложное падение. Особенно
вероятно на Linux, где представление `WCHAR_T` и строк в компоненте отличается
от Windows.

Проверка: найти в компоненте места, где заполняется `VTYPE_PSTR` (в `src/`), и
либо перевести их на `VTYPE_PWSTR`, либо зафиксировать расхождение в тестах как
известное ограничение OneScript.

### 2.4. `VTYPE_TM` конвертируется через `mktime` — зависит от часового пояса

`TmToOleDate` строит `struct tm` и вызывает `mktime`, то есть интерпретирует
время в локальной зоне. В CI зона обычно UTC, локально — нет.

Риск: тесты с датами, возвращаемыми как `VTYPE_TM`, могут расходиться между
машиной разработчика и раннером.

Проверка: прогонять OneScript-тесты с `TZ=UTC` (задать в workflow) и не
сравнивать даты «в лоб» без учёта зоны.

### 2.5. Сигнатура `FreeVariant` изменилась — старые прокси несовместимы

`FreeVariant(tVariant*)` → `FreeVariant(tVariant*, int32_t count)`. Прокси-модуль
`ScriptEngine.NativeApi` из старых комплектов (например, ветка `oscript` в
`lintest/tools1c` с движком 1.5.0) с 2.2.0 не совместим.

Правило: не подмешивать `.so`/`.dll` прокси из сторонних комплектов — брать
только официальный дистрибутив 2.2.0.

### 2.6. `NativeApiFactory.Register` теперь идемпотентен

Повторная регистрация того же идентификатора возвращает `true` (раньше `false`),
а после `Dispose` движка — `ObjectDisposedException`.

Следствие: в `runner.os` идентификатор генерируется заново
(`"_" + СтрЗаменить(Строка(Новый УникальныйИдентификатор), "-", "")`,
строка 107), поэтому повторные прогоны в одном процессе безопасны. Если
идентификатор когда-нибудь станет фиксированным — поведение изменится.

### 2.7. Хостинг обязан включать `UseNativeApi`

`AttachAddIn` вызывает `_engine.Services.Resolve().Register(...)`. Сервис
появляется только при `UseNativeApi()`, который добавлен в `UseDefaultHosting()`.
Для CLI-сборки 2.2.0 это выполнено; при встраивании движка в свой хост
`UseNativeApi()` нужно вызывать явно.

## 2A. Системные пробелы поддержки NativeApi в OneScript 2.2.0

Ниже — не история исправлений, а текущее состояние: чего в поддержке NativeApi нет
или что работает иначе, чем в платформе 1С. Столбец «источник» различает
подтверждённое кодом OneScript и то, что нужно проверить на нашей компоненте.

| № | Пробел | Источник | Влияние на VanessaExt | Приоритет |
|---|---|---|---|---|
| 1 | Нет типов `VTYPE_I8`, `VTYPE_UI2/UI4/UI8`, `VTYPE_DECIMAL`, `VTYPE_CY`: в разборе `GetVariant` они попадают в `default` и отдаются как пустое значение | `NativeApiProxy.cpp`, `switch (v->vt)` — ветки есть только для EMPTY, I2, I4, ERROR, UI1, BOOL, R4, R8, DATE, TM, PSTR, PWSTR, BLOB | размеры файлов больше 2 ГБ, большие счётчики, денежные суммы приходят как «пусто», без ошибки | высокий |
| 2 | `VTYPE_PSTR` возвращается как `ДвоичныеДанные` (через blob-колбэк), а не как `Строка` | `NativeApiProxy.cpp`: `case VTYPE_PSTR: x(variant, number, v->pstrVal, v->strLen)` | любой метод, отдающий ANSI-строку, ломает проверки `ИмеетТип("Строка")` / `Равно`; особенно вероятно на Linux | высокий |
| 3 | Неподдерживаемый тип молча превращается в пустое значение: в `default` вызывается `e(variant, number)`, исключения нет | тот же `switch` | тесты «проходят» на пустых значениях — маскировка реальных дефектов компоненты | высокий |
| 4 | События компоненты (`ExternalEvent`) и статусные сообщения не доставляются в скрипт: в C# есть события `OnComponentEvent`, `OnComponentStatusText`, но подписаться на них из BSL негде (нет формы и аналога `ОбработкаВнешнегоСобытия`) | `NativeApiComponent.cs` — события объявлены, потребителя в языке нет | асинхронные методы и прогресс недоступны; тесты, ожидающие событие, в OneScript невозможны | высокий |
| 5 | Сообщения компоненты через `AddError` теряются: `OnComponentError` никто не слушает, в отличие от 1С, где они попадают в сообщения пользователю | `NativeApiComponent.cs`, обработчик `_onError` только вызывает событие | ошибка внутри компоненты не видна тесту: он получит пустое значение и «пройдёт» | высокий |
| 6 | Все параметры методов объявляются `.ByValue(false)`, но обратная запись идёт только в `IVariable`: если передан литерал или выражение, выходное значение теряется без ошибки | `GetMethodInfo` (`ByValue(false)`) и `WriteBackParameters` (`if (arguments[i] is IVariable)`) | расхождение с 1С: там out-параметр требует переменную, здесь — тихое игнорирование | средний |
| 7 | `VTYPE_TM` конвертируется через `mktime`, то есть в локальной зоне; `VTYPE_DATE` — через OADate | `NativeApiProxy.cpp`, `TmToOleDate` | даты, возвращённые как `struct tm`, зависят от TZ; локально и на раннере результаты разойдутся | средний |
| 8 | При регистрации библиотеки конструктор каждой компоненты вызывается дважды: `GetClassObject` → `GetExtensionName` → `DestroyObject`, затем скрипт создаёт экземпляр заново | `NativeApiLibrary.RegisterComponents` | побочные эффекты конструктора (файлы, сокеты, глобальные обработчики) выполняются «вхолостую» | средний |
| 9 | Разрядность `WCHAR_T` на Linux не проверяется: строки между `.so` компоненты и движком предполагаются совместимыми | ABI прокси, проверок нет | если наша Linux-сборка и движок расходятся по ширине `WCHAR_T`, строки приходят искажёнными без явной ошибки | средний |
| 10 | 32-битные платформы не покрыты тестами самого OneScript (`TODO` и issue #1531 в `tests/native-api.os`), macOS вне прогона | `tests/native-api.os` | Win32-сборка VanessaExt в контуре OneScript не проверяется вовсе | средний |
| 11 | Нет тестов на: даты, `I8`/`Decimal`, `PSTR`, события, несколько экземпляров компоненты, повторную регистрацию библиотеки, `Dispose` движка при живых компонентах | `tests/native-api.os` — 6 тестов, перечисленных в `ПолучитьСписокТестов` | любая регрессия в этих ветках проходит незамеченной | средний |
| 12 | Значения параметров по умолчанию читаются только для непереданных аргументов; в `GetMethodInfo` реальное значение не запрашивается (закомментировано с пометкой «кажется, что значение не нужно») | `NativeApiComponent.GetMethodInfo` | методы компоненты со значениями по умолчанию, отличными от пустого, ведут себя иначе, чем в 1С | низкий |
| 13 | Нулевой указатель компоненты не проверяется: `GetClassObject` в компоненте возвращает `0` и оставляет `*pInterface == nullptr`, OneScript создаёт объект с нулевым указателем и падает процессом (SIGSEGV), а не исключением | `NativeApiComponent` (конструктор) + поведение `GetClassObject` в VanessaExt (`src/AddInNative.cpp:68`) | обращение к классу, которого нет в данной сборке (например, `WindowsControl` в Linux), обрывает весь прогон без сообщения о причине | высокий |

### Как это соотносится с нашими тестами

- Пункты 1–3 и 5 бьют по самым частым нашим вызовам: строки, числа, размеры.
  Именно они дают «зелёный» прогон при фактически неверных значениях, поэтому
  первый прогон OneScript нужно читать не по итоговой строке «провалено: 0»,
  а по факту совпадения значений в отчёте.
- Пункты 4 и 7 касаются функционала, которого у нас в тестах пока нет
  (события, даты) — это ограничения охвата, а не текущие падения.
- Пункты 9 и 10 — риск ложной уверенности: x64-прогон не подтверждает Win32,
  а Linux-строки могут расходиться по ABI.

### Практика 2026-11-01

Прогон `oscript-linux` на 2.2.0: тест «Инициализация библиотеки» прошёл, на
следующем тесте («Свойства WindowsControl») процесс упал с `Segmentation fault
(core dumped)`, код 139. Сработал пункт 13: класса `WindowsControl` в
Linux-сборке нет, `GetClassObject` вернул нулевой указатель, OneScript его не
проверил и обратился к памяти.

Что сделано: тест исключён из Linux-набора (`Example/Forms/Autotests`, условие
`ЭтоЛинукс()`), а в `tests/oscript/runner.os` добавлена печать имени теста и
каждого шага **до** выполнения — теперь место падения видно в логе.

## 3. Чек-лист проверок для следующего сеанса

1. Прогнать `tests/oscript/runner.os` на OneScript 2.2.0 (linux-x64 и win-x64),
   зафиксировать список падающих тестов.
2. Для каждого падения отделить «баг компоненты» от «расхождения OneScript/1С»
   по пунктам 2.1–2.4 и таблице 2A.
3. Проверить, нет ли в компоненте `VTYPE_PSTR` (поиск по `src/`); при наличии —
   либо перевести на `VTYPE_PWSTR`, либо внести в известные ограничения.
4. Проверить отсутствие побочных эффектов в конструкторе компоненты
   (пункт 2.2).
5. Задать `TZ=UTC` в шагах `oscript-linux` / `oscript-windows`.
6. Снять `continue-on-error` с шагов OneScript, когда набор станет зелёным.
7. Следить за PR #1790: после вливания перепроверить тесты с выходными
   параметрами.
8. Проверить `I8`/`Decimal` (пункт 1 таблицы 2A): вызвать метод, возвращающий
   размер файла больше 2 ГБ или большое целое, и убедиться, что значение не пустое.
9. Добавить в `runner.os` защитную проверку: если метод компоненты вернул
   пустое значение там, где тест ожидает число или строку, — это провал,
   а не совпадение. Это закрывает пункт 3 таблицы 2A (молчаливый `default`).
10. Проверить потерю `AddError` (пункт 5): вызвать метод, который сообщает
    об ошибке через `AddError`, и убедиться, что тест это замечает; при
    необходимости — собирать такие сообщения в раннере.
11. Проверить out-параметр, переданный выражением (пункт 6): сравнить
    поведение OneScript и платформы 1С.
12. Проверить ABI строк на Linux (пункт 9): сверить ширину `WCHAR_T` в нашей
    сборке и в прокси-модуле движка 2.2.0.
13. Решить, нужен ли прогон `oscript-windows` для Win32-сборки (пункт 10):
    сейчас контур проверяет только x64.
