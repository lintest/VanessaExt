Навык для правки `.github`-независимого CI этого репозитория: `appveyor.yml`, `scripts/linux-1c-test.sh`, `scripts/*.ps1`.

## Главное правило: не запускать обработку через /Execute

`/Execute VanessaExt.epf` заставляет **платформу** загрузить внешний код, и она показывает модальный диалог «Предупреждение безопасности». Диалог возникает до выполнения кода обработки, поэтому:

- `УстановитьОтключениеЗащитыОтОпасныхДействий()` не помогает — по документации защита включается обратно при возврате из процедуры;
- настройка пользователя `ЗащитаОтОпасныхДействий.ПредупреждатьОбОпасныхДействиях = Ложь` помогает только со **следующего** сеанса (`ТекущийПользователь()` возвращает состояние на момент старта сеанса);
- `conf.cfg` с `DisableUnsafeActionProtection=.*` — вспомогательная страховка, не основной механизм.

Правильный путь: база грузит обработку сама.

```1c
ОписаниеЗащиты = Новый ОписаниеЗащитыОтОпасныхДействий;
ОписаниеЗащиты.ПредупреждатьОбОпасныхДействиях = Ложь;
// BSLLS:UsingExternalCodeTools-off
Обработка = ВнешниеОбработки.Создать(ИмяФайла, Ложь, ОписаниеЗащиты);
ОткрытьФорму("ВнешняяОбработка." + Обработка.Метаданные().Имя + ".Initialize", ПараметрыФормы);
```

Реализация — `Config/Ext/ManagedApplicationModule.bsl`, режимы `/C install` и `/C autotest`. Форма `Initialize` обработки сама разбирает `ПараметрЗапуска` (`install` / `autotest` / иначе `MainForm`), её менять не нужно.

## Порядок аргументов командной строки

`/C` съедает остаток строки как своё значение — **всегда ставь его последним**:

```
1cv8t.exe ENTERPRISE /LRU /F<база> /N CI /DisableStartupDialogs /DisableStartupMessages /Out install.log /C install
```

Симптом ошибки: `/C install завершился с кодом 1`, в `install.log` — «Пользователь ИБ не идентифицирован».

## Обязательные страховки от зависания

1С в интерактивном режиме может открыть модальное окно и не завершиться никогда. Поэтому:

- запуск через `Start-Process` + `WaitForExit(мс)`, при таймауте — `Kill()`;
- скриншот `VirtualScreen` в `desktop-<режим>.png` перед убийством процесса;
- `/Out <режим>.log` для каждой фазы;
- проверка `ExitCode`;
- все логи и скриншоты — в `artifacts` и печать tail'ов в `on_failure`.

## Фазы тестового прогона

1. `prepare` — создаёт пользователя `CI` с правами администратора и снимает предупреждения у всех пользователей базы, затем `ЗавершитьРаботуСистемы`. Обработка не загружается, диалогов нет.
2. `install` — под `/N CI`, установка нативной компоненты.
3. `autotest` — под `/N CI`, прогон тестов, признак успеха — файл `success.txt`.

## Сборка

- Linux: образ `Ubuntu2004`, `gcc-9`/`g++-9` (не 7 и не 18.04 — в актуальных образах AppVeyor их нет).
- Ветки, на которых идут сборки, перечислены в `branches.only`; новая ветка без этой записи молча не собирается.
- Версия: `{build}` — глобальный счётчик проекта, локального сброса при смене минорной версии нет; нужен свой базовый номер (`APPVEYOR_BUILD_NUMBER - VERSION_BASE_BUILD + 1` в секции `init`).

## Отладка

- Ссылка на сборку → `https://ci.appveyor.com/api/buildjobs/<jobId>/log` (plain text, обрезается на больших логах — надёжнее смотреть артефакты).
- Статусы джобов: `https://ci.appveyor.com/api/projects/<account>/<project>/history`.
- Первым делом смотреть `prepare.log` / `install.log` / `desktop-*.png`, а не общий лог джобы.

## Git в этом репозитории

Рабочая копия для агента — **обычный клон** (`C:\Cpp\VanessaExt-clone`). В linked worktree `.git` — файл-ссылка, и встроенный git-инструмент не умеет с ним работать (`fatal: not a git repository`), `clone` локального пути падает с `Unknown repository format`.
